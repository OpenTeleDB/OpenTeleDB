# XProxy

XProxy 是一款面向 OpenTeleDB的连接池中间件，具备会话级和事务级连接池能力，支持连接上下文维护、自动读写分离以及负载均衡等功能。它的设计目的是减少频繁创建和维护大量数据库连接所带来的资源开销，同时通过将只读请求自动转发至备节点处理，提升系统的整体吞吐量。此外，XProxy 能够自动检测连接状态，在连接空闲时间过长或发生异常时，及时进行回收并重新建立连接，避免资源备无限制地占用。

## 名词解释

- **后端连接（Backend Connection）**：后端连接是指客户端与 OpenTeleDB数据库之间建立的实际连接。在 OpenTeleDB中，每个连接对应一个独立的后端进程（Backend Process），负责处理该连接上的所有数据库操作。通过内置函数 `pg_backend_pid()` 可以查询当前连接所对应的后端进程的 PID（Process ID）。
- **事务级/会话级连接池**：连接池根据连接的生命周期和复用粒度可分为**事务级连接池**与**会话级连接池**两种模式：
  - 会话级连接池：客户端在整个会话期间始终绑定同一个后端连接，直到客户端主动断开连接或会话结束。适用于需要长时间保持状态的应用场景；
  - 事务级连接池：客户端每次执行事务时可能被分配到不同的后端连接。事务结束后释放连接回连接池，供其他请求复用。适用于高并发、短事务、无状态的业务需求。
- **PBE 协议(Extended Query)**：PBE 协议即OpenTeleDB拓展协议。该协议将客户端请求拆分为三个阶段：Parse（解析）、Bind（绑定） 和 Execute（执行）：
  - Parse将 SQL 查询语句解析为可执行的计划（Query Plan），并定义参数占位符（如 `$1`, `$2` 等）；
  - Bind将具体的参数值绑定到之前解析的查询计划中；
  - Execute执行已绑定的查询计划并返回结果；

- **用户-数据库-规则三元组:** OpenTeleDB建立连接时，需要发起者指定访问的用户、数据库，建立后的连接只能以特定用户访问指定的数据库。因此，可以共享的连接存在限制，即它们必须是有相同的用户-数据库二元组。XProxy另外为连接添加了规则，用以控制连接的行为，上述二元组拓展为用户-数据库-规则三元组，即相同用户、数据库、规则的连接才可以共享、复用。

## 功能模块

### 连接管理

#### 连接池

- **事务级、会话级连接池**
  - **相关参数**

| 名称      | 类型                               | 定义                                  |
| --------- | ---------------------------------- | ------------------------------------- |
| pool      | string    "session"或"transaction" | 使用事务级/会话级连接池               |
| pool_size | integer                            | 连接池的大小限制。默认0，表示无限制。 |

- **空闲连接释放** 

如果客户端/后端连接太长时间没有进行通信，或超出最大时间限制，XProxy根据配置参数对连接进行淘汰

- **相关参数**

| 名称                             | 类型    | 定义                                                         |
| -------------------------------- | ------- | ------------------------------------------------------------ |
| pool_timeout                     | integer | 等待连接池空闲连接的超时时间，超时时会端口客户端的连接，单位ms。默认为0，表示无限等待。 |
| pool_ttl                         | integer | 连接池中后端连接的空闲时间，当空闲时间超过该值会被cron线程关闭。默认为0。单位秒。 |
| pool_client_idle_timeout         | integer | 客户端连接不在事务中的最大空闲时间，超过该空闲时间则会断开客户端连接。单位秒。 |
| pool_idle_in_transaction_timeout | integer | 客户端连接在事务中的最大空闲时间，超过该空闲时间则会断开客户端连接。单位秒。 |
| server_lifetime                  | integer | 后端连接的存活时间上限，为了避免长期允许的PG进程cache占用太大内存，单位秒，默认值3600。 |

- **事务相关管理**

如果客户端退出时，后端仍在执行查询或处于事务中，XProxy可以指定对应的行为。

- **相关参数**

| 名称          | 类型 | 定义                                                         |
| ------------- | ---- | ------------------------------------------------------------ |
| pool_cancel   | bool | 客户端退出时，如果后端连接仍在执行查询，发送cancel中止其执行，关闭时会直接断开后端连接。默认开启。 |
| pool_rollback | bool | 客户端退出时，如果后端连接仍在事务中，发送rollback回滚事务，关闭时会直接断开后端连接。默认开启。 |

#### 上下文管理

在OpenTeleDB中存在着一些会话级资源，即客户端-后端连接存在期间生效的资源，客户端退出后这些资源自动释放。对于事务级连接池而言，一个客户端可能在不同的后端连接之间切换，因此如果没有特别处理，客户端可能会在后端连接A上建立资源，随后对其进行操作，但发现该资源不存在，因为客户端已经被调度到后端连接B上。在XProxy中，纳入管理的临时资源包括 SET/RESET GUC，消息级预编译语句（使用Parse消息创建），语句级预编译语句（使用PREPARE关键词创建）, 临时表, LISTEN CHANNEL, 游标（CURSOR）。

对于前2种资源，XProxy记录客户端对其使用的情况，并在事务级连接池发生切换时迁移到新的后端连接上；对于后4种资源，如果客户端申请了它们，则连接不能发生切换。

#### 预编译语句回收

当后端连接上预编译语句的数量超过阈值*（*pool_prepared_statement_limit*）*，或者Parse的语句长期未使用*（*pool_prepared_statement_expired_time*）*，则会使用lru算法回收掉最近不常使用的语句，避免过多的内存占用。

回收动作的两个触发时机：

1. 后台线程每隔1min进行回收(如果只依靠这种方式回收，低于1min的参数设置不生效)；
2. 执行parse消息时回收；

- **相关参数**  

| 名称                                 | 类型    | 定义                                                         |
| ------------------------------------ | ------- | ------------------------------------------------------------ |
| pool_prepared_statement_limit        | integer | 后端连接保留Prepare的语句的最大数量，超过该值，则最近最不常使用的语句会被close掉。默认为0，表示不限制保留的Prepare语句的数量。 |
| pool_prepared_statement_expired_time | integer | 后端连接保留Prepare的语句的最大空闲时间，空闲时间超过该值的语句会被close掉。默认为0，表示不限制Prepare的语句的空闲时间。 |

### 读写分离

XProxy读写分离基于query_check插件和XProxy自身粗粒度过滤实现。**在使用XProxy之前，必须检查query_check插件是否安装。**方法：select * from pg_extensions;  或 通过psql \dx命令查询。query_check插件的所有参数都**不需要手动调整。**

读写分离有以下几种使用方式：自动读写分离、基于端口的读写分离、基于Hint的读写分离。一般来说，用户应该选择自动读写分离或基于端口的读写分离的其中一种。

- **自动读写分离**

对于事务外语句，如果设置target_server_attrs为auto，可以进行自动读写分离；

开启自动读写分离：如果语句被BEGIN...END包围，由于可能破坏事务一致性，XProxy**不会进行读写分离**

- **基于Hint的读写分离**

 SQL语句前使用前缀/*+ read-only */ ，可以进行基于Hint的读写分离。即使没有开启自动读写分离，Hint语句也可以被转发至备份数据库；

- **基于端口的读写分离**

配置端口相关参数时，将port_attrs指定为read-only 或者 write-only，可以进行基于端口的读写分离。该功能优先级高于自动读写分离；

port_attrs为read-only时，**语句的只读属性需要使用者保证**；如果发送写语句，有可能发往备机并且报错

- **基于端口的读写分离与负载均衡的关系**

如果主节点weigth不为0，那么当port_attrs为read-only时，读语句也会有机会发往主机；

- **相关参数**

| 名称                        | 类型    | 定义                                                         |
| --------------------------- | ------- | ------------------------------------------------------------ |
| target_server_attrs         | string  | 指定读写分离类型。可以是： （1） “read-write”，访问主 （2） “read-only”，访问备 （3） “auto”，**自动读写分离** |
| （port模块）port_attrs      | string  | 用于指定端口的读写属性。可以是： （1）“read-write”，根据用户规则进行自动读写分离 （2）“read-only”，只读端口 （3）“write-only”，只写端口。 |
| replication_delay_threshold | integer | 如果（备机的）主备延迟低于这个值，则该备机可以转发读请求     |

### 负载均衡

XProxy支持基于权重的负载均衡，可将读请求按照权重转发到不同的节点。用户可根据业务负载特征决定节点间的的权重比例。只有开启自动读写分离时，基于权重的负载均衡才有意义；此外，一个节点参与负载均衡的前提条件是：节点心跳延迟和同步延迟都在配置允许的范围内，否则直到心跳延迟和同步延迟恢复到允许的范围内，该节点都不参与负载均衡

- **相关参数**

| 名称                           | 类型    | 定义                                                         |
| ------------------------------ | ------- | ------------------------------------------------------------ |
| （storage.endpoint模块）weight | float   | 该节点（endpoint）在负载均衡时的权重。可以使用＞1的数字。    |
| replication_delay_threshold    | integer | 如果（备机的）主备延迟低于这个值，则该备机可以转发读请求。单位微秒 |
| catchup_timeout                | integer | 节点允许的心跳落后值。心跳延迟高于这个值的节点不能发送请求。单位秒 |

### 集群监控

为了识别集群中有效的节点，XProxy持续监控节点的心跳、主备延迟、主备身份信息。XProxy 每隔 1 秒 向后端数据库节点发送探测请求，用于获取以下状态信息：

- 节点心跳状态：判断节点是否在线、响应正常；
- 主备身份信息：识别该节点是主节点还是备节点；
- 主备复制延迟（Replication Delay）：备节点相对于主节点的数据同步延迟

上述信息可通过控制台命令 `show storages;` 查看，观察后端节点的运行状态与健康状况。
